## P1 — Ana prompt (iki operatör)

```
В текущем экране Work Order один оператор. Это неверно и ломает работу цеха.

На заводе один и тот же заказ ведут ДВА разных человека:
— оператор розлива: отвечает за сырьё, считается в кг и литрах (11 человек);
— оператор упаковки: отвечает за этикетку, плёнку и короб, считается в штуках (10 человек).
Это разные люди, разные списки, и брак/потери/KPI считаются по каждому отдельно.

Сейчас поле одно, и оно же решает доступ: тот из двоих, кто в нём не записан,
не видит заказ вообще — ни детали, ни передачу материалов, ни финиш.

Переделай под две роли:

1a — колонка «Оператор» становится колонкой «Операторы»: две строки в одной
ячейке, у каждой ролевой чип «Розлив» / «Упаковка». Пустая роль показывается
красным «не назначен», а НЕ прочерком — это блокер запуска, его должно быть
видно из списка. Массовое действие «Назначить операторов».

1d — в шапке заказа блок с обоими операторами и ролями. Если упаковщик не
назначен — предупреждение «Запуск заблокирован». В таблице материалов добавь
колонку «Ответственный»: она берётся из роли позиции в справочнике
номенклатуры (сырьё → розлив, упаковка → упаковка), НЕ из единицы измерения.
Внизу таблицы два итога отклонения от BOM — по одному на роль.

1e — киоск показывает оператору только его часть одного и того же заказа:
разливщик не видит лист этикеток, упаковщик не видит списание сливок. Внизу
строка «упаковку ведёт: <имя> — его позиции на ваш KPI не попадают».

Нарисуй отдельно диалог «Назначить операторов»: два поиска по людям, рядом с
каждым его линия и смена, и правило «один человек не может занимать обе роли в
одном заказе» — покажи это состояние с ошибкой и заблокированной кнопкой
«Сохранить». Добавь в диалог кнопку «Поменять местами»: обмен двух людей
должен проходить одним действием.
```

## P2 — Oluşturma modalı

```
Покажи модальное окно «Новый производственный заказ» с двумя операторами —
в трёх состояниях: пустое, заполненное корректно, и с ошибкой «один человек в
обеих ролях». Рядом с каждым человеком в списке — его обычная роль, линия и
смена, чтобы начальник смены не ставил разливщика на упаковку по ошибке.
```

## P3 — Kiosk, rol rol tam senaryo

```
Разверни киоск в полный сценарий смены ОТДЕЛЬНО для каждой из двух ролей,
экран за экраном: вход по бейджу → мои заказы → старт с вводом фактического
времени → пауза с выбором причины из каталога простоев → запись выпуска →
«Финиш» черновиком → подтверждение.

Лист ввода разный: у разливщика — килограммы сырья, у упаковщика — штуки
этикетки и короба. Черновик финиша переживает выход оператора из системы.
Кнопки 56–64 px, планшет, работа в перчатках. prompt() заменить клавиатурой
с остатком по заказу и кнопкой «Всё».
```

## P4 — Meta prompt (her turda tekrarlayın)

```
Для каждого экрана в подписи помечай явно: (а) что работает на текущем API
stabler.api.manufacturing, (б) что требует нового поля в Work Order или Item,
(в) что требует нового эндпоинта. Экран без такой пометки считается
непроверенным.
```

## Neden bu sırayla

`P1` tek başına kararı görünür kılıyor — liste, detay ve kiosk aynı turda.
`P2` sadece giriş noktası. `P3` asıl iş (vardiya akışı), ama ancak roller
yerine oturduktan sonra anlamlı. `P4` tasarımın kendi kendini denetlemesi için;
tasarım şu an bunu düzensiz yapıyor ve hangi ekranın backend istediği karışıyor.
